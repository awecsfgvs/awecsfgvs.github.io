改一行 base_url
我把项目的 API 全迁到了一个中转站

同一份代码，改一行 base_url。多模型一个入口，按量计费，五分钟跑通第一个请求。也有它不适合的场景——都写在下面。

写代码的人大概都有过这种经历：项目跑通了，卡在最后一步——调模型。

不是不会写，是链路太脏。账号要走流程，额度审批排队等半天；网络时通时断，重试逻辑写得比业务代码还长；换个模型要从头读一遍文档，SDK 参数名字对不上，改到怀疑人生。最气的是你好不容易把 A 家的接口调顺了，想试试 B 家的效果，发现自己又得重写一遍请求层。

前后折腾了小半年，试过直连、试过自建代理、试过让朋友代付，最后落地的方案其实很朴素：把所有请求收敛到同一个 OpenAI 兼容的入口上。

改动只有一行

如果你的项目本来就在用 OpenAI 那套协议，迁移成本基本为零：

# 之前
base_url = "https://api.openai.com/v1"

# 现在
base_url = "https://你的中转站域名/v1"

key 换掉，模型名按站点文档填，跑起来。LangChain、LlamaIndex、Dify、Cherry Studio、Chatbox、One API 这类工具基本都支持自定义 base_url，填进去就能用，业务代码一行不用动。

四点真实体感

01注册到跑通，五分钟

拿 key、改一行 base_url、发第一个请求，中间没有等待审批的环节。对"先跑通再说"的场景，启动成本比参数表重要——省下来的时间都写业务了。

02多模型一个入口，切换是改字符串

同一个 key、同一个地址，模型名写哪个就跑哪个。做对比测试时特别爽：同一段 prompt 丢给三个模型，代码一行不用改，只看输出。

03按量计费，没有月费绑定

用多少算多少。项目间歇性开发的时候不会白交钱，跑批处理任务时成本也可控，心里有数。

04工具链零适配

所有认自定义 base_url 的客户端、插件、Agent 框架，填入地址即可。不用为每家模型写一套适配层。

也说清楚它不适合谁

软文全是好话就没人信了，所以这几点必须摆出来：

使用前三件事

  • 中转不是官方直连。稳定性和模型版本取决于站方的上游，重要生产系统请自己做降级和重试，别把鸡蛋放一个篮子。
  • 计费倍率、可用模型、限流策略各家差别很大。选之前看清楚页面说明，别拿别人的截图当自己的预期。
  • 涉及敏感数据的场景，先确认数据处理策略。这一点比省钱重要得多。

适合谁？个人开发者、小团队、做原型验证的、需要多模型对比的、公司报销流程太慢自己先垫钱把活干了的。

如果你有稳定的海外资源和采购渠道，官方直连当然更省心；但如果你只是想"今天就把这个东西跑起来"，中转站是最短路径。
